# 유료2(개인 재무 리포트) 인테이크 스키마 — 설계 문서

이번 라운드는 코드/DB를 만들지 않는다. 유료2가 실제로 구현될 때 운영자의
상담 기록(온라인 재무상담 신청자 리포트, 대면 상담 녹취 등)에서 무엇을
뽑아 저장할지 미리 정의만 해둔다.

**원칙**: 제품이 실제로 쓰는 것은 개별 사례가 아니라 패턴/집계다. 개인
식별정보(이름·연락처·직장명·지역 상세)는 반입 단계에서 제거한다. 사례를
인용할 때는 비식별 + 재구성 형태로만.

## 필드 목록

| 필드 | 값 출처 | 비고 |
|---|---|---|
| 재물 유형 | 앱 계산값 재사용 — `WealthTypeCode`(`src/lib/wealth-type-copy.ts`): `ACCUM`/`LEAK`/`HOLD`/`TIGHT` | 상담자의 무료 결과와 동일한 코드 체계 |
| 수입 구간 | 앱 옵션 재사용 — `INCOME_RANGE_OPTIONS`(`src/lib/reality-input.ts`) | 200만원 미만 / 200~400 / 400~700 / 700 이상 / 들쭉날쭉 |
| 고정지출 비중 | 앱 옵션 재사용 — `EXPENSE_LEVEL_OPTIONS`(`src/lib/reality-input.ts`) | 소득 대비 훨씬 적음~많음 4단계 |
| 부채 유무·비중 | 앱 옵션 재사용 — `DEBT_OPTIONS`(`src/lib/reality-input.ts`) | 없음 / 1천만원 이하 / 1천~5천 / 5천 이상 |
| 상담 시점 고민 | 앱 옵션 재사용 — `MAIN_CONCERN_OPTIONS`(`src/lib/reality-input.ts`) | 돈이 안 모임 / 소득 부족 / 이직·사업 고민 / 빚 정리 / 막연한 불안 |
| 이미 해봤던 것 | **운영자 전용 신규 필드** — 자유기술(텍스트) | 앱에 대응 enum 없음. 유료1(재무 설문) 구현 시 "해봤다/그만뒀다" 구조화 응답이 생기면 그쪽 스키마와 통합 검토 |
| 첫 처방 | **운영자 전용 신규 필드** — 자유기술(텍스트) | 상담자가 그 자리에서 받은 실제 처방 원문 |
| 실행 여부 | **운영자 전용 신규 필드** — boolean + 날짜(선택) | 처방을 실제로 실행했는지, 언제부터 |
| 이후 변화 | **운영자 전용 신규 필드** — 자유기술 + 숫자 변화량(선택) | 예: 저축률 변화(%), 부채 감소액 등 정량화 가능하면 같이 기록 |

## 반입 체크리스트 (실제 구현 시)

1. 이름·연락처·직장명·지역 상세 제거(마스킹이 아니라 삭제)
2. 위 표의 "운영자 전용 신규 필드"는 상담 기록에 없는 필드이므로, 운영자가
   과거 기록을 다시 훑어보며 채워야 하는 항목 — 자동 추출 불가
3. "재물 유형"은 상담 당시 생년월일이 있으면 `classifyWealthType()`로
   소급 계산 가능(순수 함수, 새 계산 없음)
